# Supplied-event ledger v1 / synthetic receipt v2 — review draft

Canonical claim: https://github.com/spik3r/heisentick-backlog/pull/564 . Producer base `383b1c618aeab1bc7a64afdc3f31cc501c14f4a4`. This is an independently specified offline accounting ledger, not a Pine execution adapter, DSL strategy, averaged-position implementation, market fill simulator or a qualification result. Prior inspector stays inspection-only. No historical input, browser/forward registration, release or broker route is added.

## Strict envelope

Request exact keys: `schema`, `profile`, `instrument`, `account`, `window`, `events`, `requestedSemantics`. `schema=synthetic-ledger-request-v1`, `profile=supplied-event-ledger-v1`. Unknown keys, null required fields, duplicate JSON keys, nonfinite/coerced values and malformed IDs are invalid. No implicit defaults. Input bytes capped at1MiB; at most1024 events. IDs are ASCII `[A-Za-z][A-Za-z0-9_-]{0,63}`. Decimal strings match `0|[1-9][0-9]*` with optional `.[0-9]{1,12}`, at most18 integral digits; no exponent/sign/whitespace. Prices, pointValue, tickSize, quantityStep and leverage must be positive. Quantities positive exact multiples of quantityStep; prices exact multiples of tickSize. Arithmetic uses exact rationals, no intermediate rounding. Amount outputs are reduced canonical `numerator/denominator` strings including `0/1`; prices/quantities also rational strings. This synthetic rule is not Pine binary64/tick rounding parity.

Instrument exact keys: `id`, `priceCurrency`, `accountCurrency`, `pointValue`, `tickSize`, `quantityStep`, `conversion`, `session`. Currencies uppercase3 ASCII. Require priceCurrency=accountCurrency, conversion=`identity`, session=`synthetic-continuous`. Other conversion/session requests are unsupported; no real feed is admitted. Symbol name must start `SYNTH_`.

Account exact keys: `initialBalance`, `leverage`, `marginPolicy`, `feePolicy`, `terminalPolicy`, `positionPolicy`. InitialBalance positive. Supported policies: `initial-only-no-liquidation`, `{kind:fixed-per-full-filled-order,amount:<nonnegative decimal>}`, `keep-open`, `single-position-no-additions`. No percent, spread, slippage, funding, tax, fee allocation, maintenance call/liquidation or forced terminal close is inferred. Those policies are unsupported. Leverage is a synthetic rational, not a TradingView margin setting.

Window exact keys: `startT`, `endT`; integer epoch milliseconds in JS-safe domain `0..9007199254740991`, startT<endT. Timestamps express explicit event instants, not candle open labels. Closed supplied-event domain includes BOTH boundary instants `[startT,endT]`; this deliberately permits a final-close submission pending at terminal. This is not the historical candle selection interval. Every event has exact `eventId`, `t`, `seq`, `phase`, `kind` plus kind-specific fields. Seq is contiguous0..n-1. Order strictly by `(t,phaseRank,seq)`, phaseRank submit10,fill20,cancel30,mark40,terminal50. At the same t phase may only advance/stay equal; seq disambiguates same-phase events. No hidden intrabar path/tick is inferred. Exactly one terminal event, last, at endT. Empty event list invalid. An endT submit then terminal is admitted and stays pending if no fill supplied.

`requestedSemantics` must be an array of unique strings. Supported value is empty array. Recognized unsupported strings: `pine-admission`, `bracket-refresh`, `reversal`, `stop-target-collision`, `partial-fill`, `averaging`, `historical`, `forced-liquidation`. An unknown string is invalid. Unsupported checks precede transitions. Whole request is atomic: failure emits no admitted receipt or partial state.

## Identities and transitions

All event IDs globally unique. Order IDs globally unique at submit and never reusable. Position IDs globally unique for entry submit (even cancelled) and never reused. Allocation IDs globally unique for exit submit (even cancelled). Reference fields must match the live object exactly; cross-position/unknown/replayed references invalid. Position and allocation namespaces are distinct; no exit-ID stripping.

Submit event phase=`submit`, kind=`submit`, extra exact fields `orderId`, `role`, `positionId`, `side`, `qty`, `allocationId`. Role entry/exit; side long/short means position direction, not transaction sign. Entry allocationId MUST null, exit allocationId MUST an ID. Entry allowed only flat and with no pending entry or exit; opening or pending another entry returns `UNSUPPORTED_ADDITION` (covers losing/winning adds equally). Opposite-direction entry while open returns `UNSUPPORTED_REVERSAL`, no silent close/netting. Exit requires a live position, same positionId/side, full exact position quantity and no other pending exit; mismatch invalid. Exit submit reserves its whole position quantity to its allocationId. No bracket/limit/stop fields allowed; requested bracket semantics unsupported. Entry orders submitted flat cannot retrospectively pass through a live-position addition.

Fill event phase=`fill`, kind=`fill`, exact extras `orderId`, `positionId`, `allocationId`, `qty`, `price`. References match the pending order. Full exact order quantity only; any partial qty is `UNSUPPORTED_PARTIAL_FILL` (zero qty invalid). Explicit price admitted on tick; ledger never infers eligibility/next-open/gap/touch/collision. A pending entry fill creates one position instance. Charge one fixed fee for this fully filled order. Check post-fee available balance >= required initial margin `qty*price*pointValue/leverage`; reject `INVALID_INITIAL_MARGIN` atomically otherwise. No averaging/tranches. Position entry price equals supplied price. Entry-fill valuation starts at supplied fill price; this is a transaction valuation, not a quote. Exit fill realizes signed `(exit-entry)*qty*pointValue`, debits ONE fixed exit fee, releases reservation and closes position. Exit allocation receipt links orderId, allocationId, positionId and closed qty. Fee is not distributed among hypothetical tranches. Exits may realize losses leaving negative balance; no liquidation simulation. Consumed order cannot fill twice.

Cancel event phase=`cancel`, kind=`cancel`, exact extras `orderId`, `positionId`, `allocationId`. Pending order must exist and references match. Cancel releases reservation, retains tombstoned identities; charges zero fee. No replace inference. Mark event phase=`mark`, kind=`mark`, exact extras `positionId`, `price`. Requires live matching position; sets explicit valuation mark. Equity=balance+signed(mark-entry)*qty*pointValue. Marks do not change balance, fee or required entry margin. Initial-only margin does not trigger hidden maintenance/stopouts.

Terminal phase=`terminal`, kind=`terminal`, no extra fields. With open position, an explicit mark at endT is REQUIRED before terminal (INVALID_TERMINAL_MARK otherwise); terminal does not close it or charge another fee. Flat terminal needs no mark. Pending orders and reservations retained, no fee for unfilled orders. Pending entry may coexist only with flat state. Pending exit may coexist with its one live position. Initial state always flat, no orders, zero fees/realized/unrealized, balance=initialBalance; imported live state unsupported.

## Receipt and typed results

Success exact `schema=synthetic-ledger-receipt-v2`, `profile`, `status=synthetic-success`, `qualification=unqualified-not-Pine-parity`, echoed strict envelope and ordered lifecycle, `completedTrades`, `terminal`. Lifecycle retains every event, order/position/allocation reference, transitions and exact before/after economic state. Completed trade retains entry/exit order IDs, positionId, allocationId, entry/exit event/t/phase/seq, direction, qty, prices, gross realized, entryFee, exitFee, totalFee and net realized. Terminal retains watermark `{t,phase,seq}`, initialBalance, balance, cumulative gross realized, cumulative fees, unrealized, equity, openPosition or null, sorted pending orders, allocation reservations, current mark event/price/t or null, and used identity tombstones. Deterministic list order is submission seq, never map iteration. No receipt-v1 compatibility projection.

Failure exact `schema=synthetic-ledger-result-v1`, `profile`, `status=invalid-input|unsupported`, `code`, `eventId` or null, `receipt=null`. Structural invalid input wins before unsupported request semantics, then first unsupported requested semantics in lexicographic order wins, then first transition error in supplied order. Codes include INVALID_SCHEMA/DECIMAL/GRID/ORDERING/IDENTITY/REFERENCE/INITIAL_MARGIN/TERMINAL_MARK and UNSUPPORTED_ADDITION/REVERSAL/PARTIAL_FILL/BRACKET_REFRESH/COLLISION/PINE_ADMISSION/CONVERSION/SESSION/POLICY/HISTORICAL. Errors contain no partial economic outputs. Final code registry/field schema reviewed before implementation.

## Review and verification

Manual fixture `engine/suppliedledger/testdata/receipt-v2-manual.json` uses invented explicit fills and economic rational identities. Expected outputs are authored independently, not regenerated by the engine. Reject malformed shape, absent envelope, unknown fields, duplicate IDs, replay, bad grid/order, unsupported adds/reversal/refresh/collision/Pine and partial fills. Test cancelled IDs stay reserved, boundary pending/no fee, terminal open mark/no forced fee, profitable/loss close and insufficient initial margin. Prefix tests compare supplied-event snapshots only for complete prefixes (append terminal at declared boundary with required mark); never insert a mark/terminal into original prefix and call it causal parity.

Implement only after Astra's spec review: separate Go package/CLI, strict JSON decoding and bounded exact rational accounting, pinned Go1.22.12/Node24 native/WASM equality for the synthetic package, existing family checks unchanged, explicit repository memory validation and independent final review. No existing receipt comparator or inspector is relabeled. Actual Pine fills/admission, historical study/holdouts, realistic trading costs and product integration remain unavailable and outside this slice.

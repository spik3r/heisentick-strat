# Supplied-event ledger v1 / synthetic receipt v2 — review draft

Canonical claim: https://github.com/spik3r/heisentick-backlog/pull/564 . Current producer base `36cde2b0f5c9e56166e67a704a17691c565cf372` (actual squash merge). Original spec head5285e3c and validation against383b1c6 are retained as pre-restack historical evidence, not fresh validation. This is an independently specified offline accounting ledger, not a Pine execution adapter, DSL strategy, averaged-position implementation, market fill simulator or a qualification result. Prior inspector stays inspection-only. No historical input, browser/forward registration, release or broker route is added.

## Strict envelope

Request exact keys: `schema`, `profile`, `instrument`, `account`, `window`, `events`, `requestedSemantics`. `schema=synthetic-ledger-request-v1`, `profile=supplied-event-ledger-v1`. Unknown keys, null required fields, duplicate JSON keys, nonfinite/coerced values and malformed IDs are invalid. No implicit defaults. Input bytes capped at1MiB; at most1024 events. IDs are ASCII `[A-Za-z][A-Za-z0-9_-]{0,63}`. Decimal strings match `0|[1-9][0-9]*` with optional `.[0-9]{1,12}`, at most18 integral digits; no exponent/sign/whitespace. Prices, pointValue, tickSize, quantityStep and leverage must be positive. Quantities positive exact multiples of quantityStep; prices exact multiples of tickSize. Arithmetic uses exact rationals, no intermediate rounding. Amount outputs are reduced canonical `numerator/denominator` strings including `0/1`; prices/quantities also rational strings. This synthetic rule is not Pine binary64/tick rounding parity.

Instrument exact keys: `id`, `priceCurrency`, `accountCurrency`, `pointValue`, `tickSize`, `quantityStep`, `conversion`, `session`. Currencies uppercase3 ASCII. Require priceCurrency=accountCurrency, conversion=`identity`, session=`synthetic-continuous`. Other conversion/session requests are unsupported; no real feed is admitted. Symbol name must start `SYNTH_`.

Account exact keys: `initialBalance`, `leverage`, `marginPolicy`, `feePolicy`, `terminalPolicy`, `positionPolicy`. InitialBalance positive. Supported policies: `initial-only-no-liquidation`, `{kind:fixed-per-full-filled-order,amount:<nonnegative decimal>}`, `keep-open`, `single-position-no-additions`. No percent, spread, slippage, funding, tax, fee allocation, maintenance call/liquidation or forced terminal close is inferred. Those policies are unsupported. Leverage is a synthetic rational, not a TradingView margin setting.

Window exact keys: `startT`, `endT`; integer epoch milliseconds in JS-safe domain `0..9007199254740991`, startT<endT. Timestamps express explicit event instants, not candle open labels. Closed supplied-event domain includes BOTH boundary instants `[startT,endT]`; this deliberately permits a final-close submission pending at terminal. This is not the historical candle selection interval. Every event has exact `eventId`, `t`, `seq`, `phase`, `kind` plus kind-specific fields. Seq is contiguous0..n-1. Order strictly by `(t,phaseRank,seq)`, phaseRank submit10,fill20,cancel30,mark40,terminal50. At the same t phase may only advance/stay equal; seq disambiguates same-phase events. No hidden intrabar path/tick is inferred. Exactly one terminal event, last, at endT. Empty event list invalid. An endT submit then terminal is admitted and stays pending if no fill supplied.

`requestedSemantics` must be an array of unique strings. Supported value is empty array. Recognized unsupported strings: `pine-admission`, `bracket-refresh`, `reversal`, `stop-target-collision`, `partial-fill`, `averaging`, `historical`, `forced-liquidation`. An unknown string is invalid. Unsupported checks precede transitions. Whole request is atomic: failure emits no admitted receipt or partial state.

## Identities and transitions

All event IDs globally unique. Order IDs globally unique at submit and never reusable. Position IDs globally unique for entry submit (even cancelled) and never reused. Allocation IDs globally unique for exit submit (even cancelled). Reference fields must match the live object exactly; cross-position/unknown/replayed references invalid. Position and allocation namespaces are distinct; no exit-ID stripping.

Submit event phase=`submit`, kind=`submit`, extra exact fields `orderId`, `role`, `positionId`, `side`, `qty`, `allocationId`. Role entry/exit; side long/short means position direction, not transaction sign. Entry allocationId MUST null, exit allocationId MUST an ID. Entry allowed only flat and with no pending entry or exit; opening or pending another entry returns `UNSUPPORTED_ADDITION` (covers losing/winning adds equally). Opposite-direction entry while open returns `UNSUPPORTED_REVERSAL`, no silent close/netting. Exit requires a live position, same positionId/side, full exact position quantity and no other pending exit; mismatch invalid. Exit submit reserves its whole position quantity to its allocationId. No bracket/limit/stop fields allowed; requested bracket semantics unsupported. Entry orders submitted flat cannot retrospectively pass through a live-position addition.

Fill event phase=`fill`, kind=`fill`, exact extras `orderId`, `positionId`, `allocationId`, `qty`, `price`. References match the pending order. Full exact order quantity only; any partial qty is `UNSUPPORTED_PARTIAL_FILL` (zero qty invalid). Explicit price admitted on tick; ledger never infers eligibility/next-open/gap/touch/collision. A pending entry fill creates one position instance. Charge one fixed fee for this fully filled order. Check post-fee available balance >= required initial margin `qty*price*pointValue/leverage`; reject `INVALID_INITIAL_MARGIN` atomically otherwise. No averaging/tranches. Position entry price equals supplied price. Entry-fill valuation starts at supplied fill price and currentMark=null; this is a transaction valuation, not a quote. Mark replaces currentMark with that event. Close clears currentMark. Reopen never inherits a prior position mark; its initial unrealized is zero until a new mark. Required terminal endT mark cannot be inherited. Exit fill realizes signed `(exit-entry)*qty*pointValue`, debits ONE fixed exit fee, releases reservation and closes position. Exit allocation receipt links orderId, allocationId, positionId and closed qty. Fee is not distributed among hypothetical tranches. Exits may realize losses leaving negative balance; no liquidation simulation. Consumed order cannot fill twice.

Cancel event phase=`cancel`, kind=`cancel`, exact extras `orderId`, `positionId`, `allocationId`. Pending order must exist and references match. Cancel releases reservation, retains tombstoned identities; charges zero fee. No replace inference. Mark event phase=`mark`, kind=`mark`, exact extras `positionId`, `price`. Requires live matching position; sets explicit valuation mark. Equity=balance+signed(mark-entry)*qty*pointValue. Marks do not change balance, fee or required entry margin. Initial-only margin does not trigger hidden maintenance/stopouts.

Terminal phase=`terminal`, kind=`terminal`, no extra fields. With open position, an explicit mark at endT is REQUIRED before terminal (INVALID_TERMINAL_MARK otherwise); terminal does not close it or charge another fee. Flat terminal needs no mark. Pending orders and reservations retained, no fee for unfilled orders. Pending entry may coexist only with flat state. Pending exit may coexist with its one live position. Initial state always flat, no orders, zero fees/realized/unrealized, balance=initialBalance; imported live state unsupported.

## Receipt and typed results

All JSON objects below have EXACT listed fields; no extension/unknown/null-coercion accepted. Input economics are decimal STRINGS under the request grammar; t/seq are raw bounded JSON integer NUMBERS. Output economics/price/qty are reduced rational STRINGS, including negative realized/balance as needed. Output t/seq remain integer numbers. Echoed input event/instrument/account data retains original decimal strings and nulls; echoed inputs are never misread as normalized rational outputs.

Success fields: `schema`, `profile`, `status`, `qualification`, `envelope`, `lifecycle`, `completedTrades`, `terminal`. Constants synthetic-ledger-receipt-v2 / supplied-event-ledger-v1 / synthetic-success / unqualified-not-Pine-parity. envelope={instrument,account,window,requestedSemantics} exact raw request echo. lifecycle array elements={event,before,after}; event is exact raw input echo, before/after are State. No extra input schema/profile in envelope.

State={balance,grossRealized,fees,unrealized,equity,openPosition,pendingOrders,reservations,currentMark,usedIds}. First5 rational strings. openPosition=null or {positionId,side,qty,entryPrice,entryOrderId,entryEventId,entryT,entryPhase,entrySeq,entryFee,requiredInitialMargin}; numeric entryT/entrySeq, phase fill, economic fields rational. pendingOrders array of {orderId,role,positionId,side,qty,allocationId,submittedEventId,t,phase,seq}; qty rational, phase submit, allocationId null for entry. reservations array of {allocationId,orderId,positionId,qty}; qty rational. currentMark=null or {eventId,t,phase,seq,positionId,price}; phase mark, price rational. usedIds={events,orders,positions,allocations}, arrays of string IDs in first-use seq order. Event ID enters usedIds.events on every successful event including terminal; other namespaces enter at submit and survive cancellation/close. State before contains no current event ID; after contains it. Initial State zeros all economics except balance/equity=initialBalance, all arrays empty and position/mark null. All arrays order by first admission/submission seq, never map order.

completedTrades array of {positionId,side,qty,entryOrderId,exitOrderId,allocationId,entryEventId,entryT,entryPhase,entrySeq,exitEventId,exitT,exitPhase,exitSeq,entryPrice,exitPrice,grossRealized,entryFee,exitFee,totalFee,netRealized}. Phases fill, times/sequences numbers, IDs/side strings, economics rational strings. netRealized=grossRealized-entryFee-exitFee; cumulative gross excludes fees. terminal={watermark,initialBalance,state}, watermark={t,phase,seq} with terminal phase, initialBalance rational, state exactly final lifecycle.after (including terminal event ID). Pending reservations retained; no receipt-v1 projection. States retain explicit used-ID tombstones and marks independently of completed trades.

Failure EXACT fields: `schema`, `profile`, `status`, `code`, `eventId`, `receipt`. schema synthetic-ledger-result-v1, profile ALWAYS supplied-event-ledger-v1 even for invalid requested profile, status invalid-input or unsupported, receipt ALWAYS null. eventId is null for global/envelope/requested-semantics errors and for malformed/non-ID eventId; for a valid-ID event with local error it is that ID. No partial economic output or echo. All negative fixtures assert the complete failure object.

Freeze refusal precedence:
1. Decode bounded JSON and reject duplicates/unknown keys/exact shapes/types/constants/lexical decimals/positive quantities, prices and parameters; unknown policy or semantics names invalid schema. Then preflight ALL events in seq order for valid IDs, unique event IDs (INVALID_IDENTITY), phase/kind agreement, contiguous seq/window bounds/monotone phase/time/exact last terminal (INVALID_ORDERING), quantity/price grid (INVALID_GRID). At the first structural/preflight error stop, even if a later/earlier request names unsupported behavior. Error in field checks follows schema field order as documented, not map iteration. Entry event field order eventId,t,seq,phase,kind,orderId,role,positionId,side,qty,allocationId; fill field order eventId,t,seq,phase,kind,orderId,positionId,allocationId,qty,price; cancel similarly without qty/price; mark eventId,t,seq,phase,kind,positionId,price; terminal base fields only. Envelope field order schema,profile,instrument,account,window,events,requestedSemantics. Instrument/account fields follow envelope lists above.
2. Envelope capabilities in priority order: conversion or currency mismatch -> UNSUPPORTED_CONVERSION; session -> UNSUPPORTED_SESSION; account policies in marginPolicy,feePolicy,terminalPolicy,positionPolicy order -> UNSUPPORTED_POLICY. Recognized unsupported alternatives: conversion fx-dynamic, session exchange-calendar, marginPolicy maintenance-liquidation, feePolicy.kind percent, terminalPolicy force-close, positionPolicy averaged. No guessed unknown enum accepted. Currencies can differ structurally but unsupported conversion wins.
3. Requested semantics in lexicographic order, mapping below. This is after envelope capabilities, before any transition.
4. Transitions in event order: at submit ID reuse INVALID_IDENTITY precedes live reference checks; entry while open opposite side UNSUPPORTED_REVERSAL, otherwise open/pending entry UNSUPPORTED_ADDITION. Exit position/side/reference INVALID_REFERENCE, qty mismatch INVALID_FILL_QTY, existing reserved exit INVALID_REFERENCE. At fill references/order liveness INVALID_REFERENCE precede qty classification: underfill positive qty -> UNSUPPORTED_PARTIAL_FILL, overfill -> INVALID_FILL_QTY; exact qty then entry postfee margin INVALID_INITIAL_MARGIN. Cancel/mark references INVALID_REFERENCE. Terminal missing same-position endT mark INVALID_TERMINAL_MARK. Strict schema/lexical/grid errors already precede transitions. For close negative balance allowed; no hidden liquidation.

Complete code/status map:
- invalid-input: INVALID_SCHEMA (including JSON bounds/duplicate keys/types/null/unknown enums/constants), INVALID_DECIMAL (economic string grammar/positive requirement), INVALID_GRID, INVALID_ORDERING, INVALID_IDENTITY, INVALID_REFERENCE, INVALID_FILL_QTY, INVALID_INITIAL_MARGIN, INVALID_TERMINAL_MARK.
- unsupported request names: averaging -> UNSUPPORTED_AVERAGING; forced-liquidation -> UNSUPPORTED_FORCED_LIQUIDATION; bracket-refresh -> UNSUPPORTED_BRACKET_REFRESH; reversal -> UNSUPPORTED_REVERSAL; stop-target-collision -> UNSUPPORTED_COLLISION; pine-admission -> UNSUPPORTED_PINE_ADMISSION; partial-fill -> UNSUPPORTED_PARTIAL_FILL; historical -> UNSUPPORTED_HISTORICAL.
- unsupported envelope/transition: UNSUPPORTED_CONVERSION, UNSUPPORTED_SESSION, UNSUPPORTED_POLICY, UNSUPPORTED_ADDITION, UNSUPPORTED_REVERSAL, UNSUPPORTED_PARTIAL_FILL. No undocumented fallback code.

Initial margin fee boundary: balance1000, qty10, price100, leverage1, fee0.25: margin1000 versus postfee999.75 => INVALID_INITIAL_MARGIN. With initialBalance1000.25: postfee1000 equals margin1000 => ACCEPT. Both have full grid-valid fills. These paired cases detect margin-before-fee and erroneous strict-greater mutants.

## Review and verification

Manual fixture `engine/suppliedledger/testdata/receipt-v2-manual.json` uses invented explicit fills and economic rational identities. Expected outputs are authored independently, not regenerated by the engine. Reject malformed shape, absent envelope, unknown fields, duplicate IDs, replay, bad grid/order, unsupported adds/reversal/refresh/collision/Pine and partial fills. Test cancelled IDs stay reserved, boundary pending/no fee, terminal open mark/no forced fee, profitable/loss close and insufficient initial margin. Prefix tests compare supplied-event snapshots only for complete prefixes (append terminal at declared boundary with required mark); never insert a mark/terminal into original prefix and call it causal parity.

Implement only after Astra's spec review: separate Go package/CLI, strict JSON decoding and bounded exact rational accounting, pinned Go1.22.12/Node24 native/WASM equality for the synthetic package, existing family checks unchanged, explicit repository memory validation and independent final review. No existing receipt comparator or inspector is relabeled. Actual Pine fills/admission, historical study/holdouts, realistic trading costs and product integration remain unavailable and outside this slice.

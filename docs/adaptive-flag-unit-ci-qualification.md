# Adaptive unit CI qualification

The ordinary Go CI job qualifies the bounded unit-report route on its actual
native runner and Node-hosted Go/WASM. It retains the existing runner selection,
read-only 1 GiB/10,000-inode capacity preflight, normal compiler settings, full
Go tests/vet/conformance, and prior raw/generic/legacy qualifications.

The immutable invented evidence bundle is self-contained. Its digest-pinned pack
materializes only declared relative regular files in a new directory, with
compressed/expanded byte and file-count limits. It contains the original source
corpus's retained core/raw and reference/comparison output bytes plus the original
invocation plan and artifact manifest. A separately identified sanitized attestation
binds the approved original checkpoint SHA without publishing its local filesystem
paths. It does not impersonate the original checkpoint. No Python reference source,
reference execution, historical data or research parameter search is needed in CI.

The bundle is an expectation set, not a live economic implementation. The Go core
and native/WASM handlers remain the only production calculation. Qualification runs
all 96 frozen source cases under each of three cost profiles. It checks complete
output bytes, allowing only the seven explicitly validated build-identity leaves
to differ, and checks exact original raw segments including whitespace/newlines.
All expected values retain their reviewed original bytes and provenance domains.

The v2 parity receipt identifies its bundle separately from the original oracle
checkpoint. The v2 transport receipt adds each ordered recovery result and both
generic refusal results to the previously approved control sequence; calls and
assertions remain the same. Prior v1 receipt artifacts remain historical evidence.

A separate validator checks complete closed receipts, exact case/control coverage,
all 576 saved report hashes, expected nonidentity output hashes, actual native/WASM
artifacts and shim, executing host, and truthful build fields. The checkout revision
is the actual checked-out commit, including a pull request's synthetic merge commit;
it is not assumed to be the PR head. Missing, truncated, duplicate, mismatched or
partial evidence fails qualification. An awaited stdout write preserves complete
large receipts before the harness exits.

CI uploads qualification receipts only when the explicit validation step succeeds.
Artifact names include run ID, run attempt and target, and missing files are errors.
No runner cleanup, security settings, credentials, release job or parallel paid job
is added. A capacity or execution failure remains a visible blocking result.

An AMD64 run qualifies that native host and its actual Go/WASM execution. The ARM64
gate requires a successful actual ARM64 native run with complete matching receipts;
cross-compilation alone is insufficient. Browser execution, measured memory/latency,
Backtester adoption, larger historical windows and account economics remain separate
gates. This job creates no producer tag or app pin.
